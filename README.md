# STEEL/LAB · 炼钢配比工作台

面向 steeluniversity **steelChallenge**（电弧炉 + 二次炼钢）的本地计算与知识库工具。单机运行、零第三方依赖，只监听 `127.0.0.1`。

## 一键启动

双击 `start.bat`（或命令行 `python app.py --open`），浏览器会自动打开 <http://127.0.0.1:8765>。

要求：Windows + Python 3.10 及以上。无需 pip 安装任何包。

## 它能做什么

| 模块             | 功能                                                                                                                                                                          |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **初始规划（默认首页）** | 开炉前把整炉路线一次定好：EAF 8 个检查点 + 二次精炼 7 个检查点，每个检查点写清“看哪个元素/温度、到什么值停、偏离了怎么处理”。装料整吨、添加剂 10 kg；分钟数只作参考节拍。可一键把整条路线载入「动态操作」画布，或打开分步向导。 |
| **全流程联动** | 每个页面顶部都有「当前炉次」流水线：炉料 → 合金 → 初始规划 → 动态实测，点任意一步直接跳转；上游改炉料/合金后，下游自动标记「需同步」，一键按当前炉次重算。初始规划会把装料单、合金单反向带到炉料页/合金页/分步向导；动态页可回写实测成分，AI 与精炼计算器读取同一份炉次；炉次记录支持载入整炉方案。 |
| **动态操作** | 不按固定时间轴：输入此刻 C/Si/Mn/Cr、温度、氧气/碳枪/功率，按元素含量外推未来曲线，给出下次取样时间、预计 C、停氧阈值和下一步动作；节点可拖拽、平移、缩放，支持“智能规划”；右侧显示与初始规划的 C 锚点对照。 |
| **操作流程** | 把 EAF 与二次精炼拆成两条**分步向导**：装料 → 熔化 → 造渣 → 吹氧 → 取样 → 合金 → 调温 → 出钢；二次精炼 CAS-OB → 钢包脱气 → LF → 连铸。每一步给出时间、用量、停止条件、红线；装料只按整吨，所有添加剂只按 10 kg；EAF 结果可一键带入二次精炼。                         |
| 炉料配比           | 内置「工程用钢（2026 赛题）」预置（C 0.50–0.56、Cr 1.50–1.60）；10 种废钢的**最小成本线性规划**；P/S/Cr/Mo/Ni/Cu 等残余元素上限、体积 ≤100 m³、单料限量；稳健模式按废钢 ±5% 波动预留约 6% 余量；熔炼收得率修正；三料斗分配（40 m³/斗、粗料 ≤30%）；±5% 废钢波动预警 |
| **EAF 造渣** | 造渣与碱度放在 EAF（手册 5.5–5.6）：CaO/SiO₂ 碱度、MgO、FeO 核算；SiO₂ 按“Si 氧化 + DRI 脉石（4.8%）+ 渣料带入”三项计算；按目标碱度/MgO 反推**一次加入**的石灰/白云石/萤石。实炉 #1552807（1160+1410+50 kg，终渣 1.698 / 8.186% / 37.117%）用于校准；推荐量额外按 FeO=45%、MgO=8.8% 设计，避免吹氧过程 FeO 升到 45–50% 时把 MgO 稀释到 8% 以下；初始规划页可改「白云石设计 FeO %」，页面同步显示 FeO 升高稀释 MgO 的曲线 |
| 总成本优化          | **配料 + 合金联合优化**：全局合金 LP（不再逐元素贪心）+ 废钢 Mn/Cr/Si 替代价值 + 模拟器 Ni 校准；目标是最低 scrap+alloy 成本。2026 工程钢 90 t 稳健模式约省 **$474/炉（2.5%）**，成本优先约省 **$659/炉（3.5%）**，并显示含电总成本                  |
| 合金补加           | EAF / 二次炼钢两套添加剂表；回收率（LF/RH/CAS-OB 与空气两档）；母合金带入 C/Si/P 的二次效应；自动避开超限；温降 −6°C/t                                                                                                |
| 二次精炼           | 按模拟器实际界面：**8 个去向**（氩站 / 德环脱气装置 / CAS-OB / 钢包炉 / 钢包脱气 / 板坯铸机 / 大方坯铸机 / 小方坯铸机）+ **21 种合金清单**（名称/单价与模拟器一致，含钙丸）；选 EAF 炉次带入脱碳后成分，手动加合金，实时核算 17 元素、合金成本和吨钢成本；支持粘贴模拟器摘要一键导入 |
| 知识库            | 两份手册 122 个知识块，BM25 中文检索，逐条给页码                                                                                                                                               |
| AI 助手          | 当前炉次状态快照（炉料/合金/规划/动态/成本）+ 计算器代理 + 手册引用；配置 OpenAI 兼容 API 后切换为 LLM Agent，能按“这炉/现在/下一步/成本/渣料”回答，不再只是关键词检索 |
| 炉次记录           | **EAF 炉次与二次精炼分开保存**：EAF 记录装料/合金/出钢成分；SM 记录选择并关联一个 EAF 炉次，自动带入出钢成分和钢水量；旧整炉记录兼容 |

## 关键假设（务必读）

1. **熔炼收得率**：`engine/charge.py` 的 `MELT_RETENTION` 已按 steeluniversity EAF 模拟器 #1552372 实炉反算：C 90%、Si 60%、Mn 85%、P 37%、S 100%、Cr 35%、Mo/Cu 100%、Ni 45%（电炉除尘灰中的 Ni 只有部分还原进入钢液）、Al 50%。预测的熔炼后 Mn≈0.47%、P≈0.012%、S≈0.010%、Cr≈0.052%，与实炉 Mn 0.45%、P 0.01%、S 0.01%、Cr 0.05% 基本吻合。界面「高级 → 熔炼收得率」仍可逐项改。
2. **合金回收率**：`eaf_cal` 档按实炉反算：Cr/Mn≈98%、C≈98%、Si≈95%、Al≈70%。Si 之前误用 82%，会把高纯硅铁多算 60–70 kg；按“目标 0.28%、实际 0.33%”反算后改为 95%。LF/RH 保护气氛仍用 `ladle` 档。
3. **EAF 钢种表**：表 2.2.1 的 PDF 文本存在列错位，C 的 TiNb 上下限按 0.010–0.050 处理；所有钢种成分在界面中均可通过计算器参数间接调整（后续可加编辑器）。
4. **成分校验对象**：校验的是“熔炼后、合金化前”的成分。C/Si/Mn 低于目标会标为「需补加」，高于目标标为「需调整」，不代表废钢方案失败。
5. **软约束**：残余元素超限时仍返回“最低可达”的方案并列出超标量，而不是直接报无解；这样可以看到 trade-off。

## 算法优化（v2）

> 2026-11-02 更新：默认装入量改为 **82 t**，电耗按 **380 kWh/t** 折算（不再写死某一炉的 34,549 kWh），其他成本默认 **0**（模拟器口径；要算电极/耐材/人工可填 37 $/t）。下面 90 t 的数字保留为历史校准记录。

- `engine/alloy_lp.py`：把合金补加从“逐元素贪心”改成**全局线性规划**，同时考虑 C/Si/Mn/Cr 的耦合、高碳锰铁的 C 夹带、高碳铬铁/硅铬的 Cr-Si 联产、普通/高纯硅铁的 Al 夹带。
- `engine/optimizer.py`：生成“基础 / 模拟器 Ni 校准 / 合金替代价值”三组候选废钢配比，对每组求最低合金成本，选 **scrap+alloy 总成本最低** 的方案。
- `POST /api/optimize/total`：返回最佳配料、合金方案、成本分解、旧版贪心对照与节省额；前端「炉料配比 → 总成本优化」按钮直接调用。
- 当前结果（2026 工程钢，90 t）：联合优化废钢 $16,608 + 合金 $1,559 = \*\*$18,167\*\*，比旧版 $18,440 省 **$273（1.5%）**。
- 操作向导按“整吨装料 + 10 kg 合金”取整后：**68 t 1号捆包 + 21 t DRI + 1 t 炉尘**；高碳铬铁 **1,950 kg** + 低碳锰铁 **430 kg** + 高碳锰铁 **170 kg** + 高纯硅铁 **280 kg**；废钢 $16,740 + 合金 $1,703 + 渣料/氧 $391 + 电 $19,693 + 其他 $3,435 = **EAF $41,962（$452.2/t）**；含二次精炼合金后整炉 **$46,297（$497.8/t）**，可直接照填模拟器。其他成本按 #715210 的 493.41 $/t 反算为 37 $/t（原 45 $/t 会整体偏高约 $8/t）。
- **注意**：电能仍是最大成本项（上炉 34,549 kWh ≈ $19,693）；算法不能替代缩短通电时间，页面会显示“含电总成本”供对比。

## 怎么用（推荐顺序）

1. 打开网站默认进入「初始规划」，选目标钢种「工程用钢（2026 赛题）」、装入量 90 t，点「生成整炉初始规划」。页面会给出关键 C 轨迹（装入 → 停氧 0.37 → EAF 出钢 ~0.54 → CAS-OB 0.45 → 脱气 0.335 → 精炼终点 ~0.38）和 EAF / 二次精炼两段全部检查点。
2. 想看每一斗怎么装、合金怎么加，页面下方有装料单和合金单（整吨 / 10 kg 档）；点「打印规划」可打 A4。
3. 点「载入动态操作 →」把整条初始路线铺到画布上；也可以点某一段的「分步向导」按 1–8 步走。
4. 执行中打开「动态操作」，填入当前 C/Si/Mn/Cr、温度和氧气流量，点「预测并给下一步建议」；右侧会同时显示当前实测 C 与初始规划锚点的偏差。它告诉你下一次取样几分钟后、预计 C 多少、吹到多少停氧。节点可拖动，点「智能规划」自动生成下一步序列。
5. 出钢后切到「操作流程 → 二次精炼」，先选一个已保存的 EAF 炉次，顶部「去」下拉按模拟器实际去向组路线（氩站 / 真空脱气 / CAS-OB / 钢包炉 / 钢包脱气 / 铸机），再在 21 种合金表里按 10 kg 档加料，点「计算成分与成本」看 17 元素和成本。
6. 需要单独算造渣/碱度时用「EAF 造渣」；二次精炼页可直接粘贴模拟器摘要里的成分/钢水量/温度，点「导入模拟器数据」自动填入。
7. 在「炉料配比」或「合金补加」调整后，点结果卡右上角「生成操作流程」/「更新操作流程」，向导会保留你调整后的配比和合金量重新生成；回到「初始规划」勾选「沿用当前炉料方案」也能按同一套料重新规划。
8. 「AI 助手」默认勾选「结合当前炉次」，会读取炉料、EAF/SM 合金、初始规划、动态实测和成本快照。未配置 API 时用本地规则；在 AI 页点「配置 API」或右上角齿轮填入 OpenAI 兼容的 base_url / model / key，即切换为 LLM Agent，会按“这炉/现在/下一步/成本/渣料/MgO”结合当前数据回答。

## 校准方法（建议）

1. 在模拟器跑一炉，记录：实际配料、熔炼后成分（或出钢成分）、合金加入量、最终成分。
2. 用「炉次记录」保存方案；把实测值与预测值对比。
3. 调整 `MELT_RETENTION`（废钢→熔炼后）与合金回收率，使预测贴近实测。
4. 校准 3–5 炉后，配比推荐会明显更准。

## 配置 LLM（可选）

右上角齿轮 → Base URL / 模型 / API Key。支持任何 OpenAI 兼容的 `/chat/completions` 接口（DeepSeek、通义千问、Moonshot 等）。Key 仅保存在本机 `data/config.json`，不会上传。未配置时使用本地 BM25 检索 + 规则回答，功能不受影响。

设置里有「获取模型列表」和「测试连接」：会实际发一次最小请求，失败时给出错误码、服务商原文和修复建议。常见问题：

| 现象 | 原因 | 处理 |
|---|---|---|
| `[401]` | Key 与当前 Base URL 不匹配（官方 Key 填到中转站，或反过来） | 换成该服务商的 Key |
| `[404]` / 返回非 JSON | Base URL 少了 `/v1` | 填 `https://api.xxx.com/v1`，测试会自动尝试补全 |
| `[503] model_not_found` | 模型名不在该站列表 | 点「获取模型列表」，从下拉里选 |
| 超时 / network | 代理、DNS 或域名写错 | 检查网络和 Base URL 拼写 |

## 部署上线

### 本机 / 局域网

```bash
python app.py                 # 只监听 127.0.0.1:8765
STEEL_LAB_HOST=0.0.0.0 python app.py   # 局域网可访问
```

### 公网（Docker）

```bash
cp .env.example .env          # 填 STEEL_LAB_TOKEN、AI Key
docker compose up -d --build
```

已提供 `Dockerfile` / `docker-compose.yml` / `.dockerignore`。没有 Docker 时，把整个目录放到任意 Python 3.10+ 主机，设置环境变量后 `python app.py` 即可。

### 环境变量

| 变量 | 作用 | 默认 |
|---|---|---|
| `PORT` | 部署平台注入的端口；设置后自动监听 `0.0.0.0` | 无 |
| `STEEL_LAB_PORT` | 本地自定义端口 | `8765` |
| `STEEL_LAB_HOST` | 监听地址 | 本机 `127.0.0.1` |
| `STEEL_LAB_TOKEN` | 访问口令；设置后所有 `/api/*`（健康检查除外）都要口令 | 空（不鉴权） |
| `STEEL_LAB_API_KEY` | AI Key，优先于 `data/config.json` | 空 |
| `STEEL_LAB_BASE_URL` / `STEEL_LAB_MODEL` | 同上，优先于文件配置 | 空 |

### 上线前必须确认

- [ ] **设置 `STEEL_LAB_TOKEN`**。公网不设口令，任何人拿到链接都能用你的 AI 额度、改配置、删炉次记录。
- [ ] **AI Key 走环境变量**，不要把 `data/config.json` 打进公开仓库或镜像（`.dockerignore` 已排除）。
- [ ] **持久化 `data/`**。`runs.json` 是你的炉次记录；容器不挂载 volume 会随重建丢失。
- [ ] **HTTPS 由平台/反向代理提供**。不要直接暴露 8765 明文端口到公网。
- [ ] 数据是单文件 JSON，适合**单人/小团队**。多人同时写入会互相覆盖（已加原子写，但仍是整表替换）；要多人用需要换数据库并按用户隔离。
- [ ] 备份 `data/runs.json` 和 `data/config.json`。
